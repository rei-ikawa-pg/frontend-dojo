メモ化された子に、**オブジェクトリテラル**（`{ id: 1 }` のようにその場で書くオブジェクト式）を渡すとどうなるか。
操作パネルの「§ 03 — Prop kind ／ prop 種別」で選択肢を **`{ id: 1 } (毎回新規)`** に切り替えてください。

### 観察のポイント

- memo があるにも関わらず、子 A が毎回 flash する
- カウンタが増え続ける

### なぜこうなるか

```tsx
// 親の中でこう書くと…
<MemoChild user={{ id: 1 }} />
// 親が再 render されて JSX が評価されるたびに
// `{ id: 1 }` は「別の新しいオブジェクト」として生成される
// memo の shallow equal は参照比較なので、毎回「違う」と判定される
```

同じことが **関数（`onClick={() => ...}`）** にも起きます。矢印関数は親が再 render されて JSX が評価されるたびに
新しい関数オブジェクトが生まれるため、memo を貫通します。

### 対策

- 参照を親側で安定させる: `useMemo(() => ({ id }), [id])` / `useCallback`
- そもそも object をまとめず primitive を渡す
- Zustand など selector を持つ store ライブラリで「本当に必要な値だけ」購読する

「memo を付けたのに止まらない」は、ほぼこの object literal か function が原因です。
