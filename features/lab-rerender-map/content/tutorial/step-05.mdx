state から計算した値を、さらに別の state として保持するパターン — いわゆる **派生 state** の罠です。

### よくある書き方

```tsx
const [items, setItems] = useState<Item[]>([])
// ❌ 派生 state
const [total, setTotal] = useState(0)
useEffect(() => {
  setTotal(items.reduce((s, i) => s + i.price, 0))
}, [items])
```

このコードは、`items` を変えた瞬間に **render → useEffect → setTotal → 再 render** の
二度手間を毎回踏みます。さらに、`items` と `total` の一時的な食い違いが起きる瞬間が生まれます。

### 観察のポイント

- 派生 state モードで「state を更新」を押す → total renders が 1 クリックで複数カウントされる
- `useMemo` or 「計算値を直接使う」モードに切り替えると 1 回の更新に収まる

### 正しい書き方

```tsx
// ✅ その場で計算 (普段はこれで十分)
const total = items.reduce((s, i) => s + i.price, 0)
// ✅ 重い計算なら useMemo
const total = useMemo(() => items.reduce((s, i) => s + i.price, 0), [items])
```

**「state にすべきか」**を判断する基準はシンプルです:
- 元 state から純粋に計算できる → state にしない
- 非同期や外部ソースから取る → state にする

この基準から外れた派生 state は、ほぼ例外なくバグを呼びます。
