# フロントエンド道場 情報設計（IA）ドラフト

最終更新: 2026-04-17 / ステータス: ドラフト

## 0. 設計原則

- **URLは意味的に読める**: `/lab/render/tutorial` のように階層と意図が分かる
- **SSG前提**: 静的生成できる構造を優先、動的パラメータは最小化
- **SEO対応**: 各Lab・各モードが独立URLを持ち、Zenn記事から直接ディープリンク可能
- **拡張性**: Phase 2, 3 でLabが増えてもURL変更なし
- **道場メタファーの節度ある活用**: URLは英語、UI表示は日本語

---

## 1. URL構造（サイトマップ）

```
/                            # ランディングページ（ヒーロー + 最新Lab紹介）
/labs                        # Lab一覧（全Labの状態一覧）
/lab/render                  # Lab 1: レンダリングパイプライン可視化（概要）
  /lab/render/tutorial       #   チュートリアルモード
  /lab/render/playground     #   自由操作モード
/lab/memory                  # Lab 2: メモリリーク稽古場（Phase 2 で追加）
  /lab/memory/tutorial
  /lab/memory/playground
/lab/jank                    # Lab 3: スクロールジャンク稽古場（Phase 3 で追加）
  /lab/jank/tutorial
  /lab/jank/playground
/about                       # 道場について（サイト理念、作者、経緯）
/roadmap                     # 修行ロードマップ（今後追加予定のLab一覧）
/privacy                     # プライバシーポリシー
/terms                       # 利用規約
/contact                     # お問い合わせ（Google Formsへ誘導）
/admin/rum                   # 管理者ダッシュボード（環境変数保護）
/api/rum/collect             # RUM収集エンドポイント（Workers）
/api/feedback                # フィードバック送信エンドポイント（Workers）
/sitemap.xml                 # サイトマップ
/robots.txt                  # robots
/not-found                   # 404（Next.jsデフォルト）
```

### URL命名ルール

- **Lab名**: 英語小文字、短く（`render`, `memory`, `jank`）
- **モード名**: `tutorial` / `playground` 固定
- **ハイフン区切り**: 複数語の場合（例: `scroll-jank` ではなく`jank`に短縮）
- **トレイリングスラッシュなし**: `/lab/render` で統一

## 2. URL決定事項と代替案

### 2.1 モードのルーティング方式【確定】

**確定**: サブルート方式（`/lab/render/tutorial`）

選定理由: SEO最強、Zenn記事からディープリンク可能、SSGビルドが自然、OGPをモード別に設定可能。

**追加設計判断**:
- モード間の状態維持は MVP では実装しない（切り替え時はリセット）
- 概要ページのモード選択は大きな2CTAボタンで明示する（小さなタブは不可）
- 深いリンク流入（Zenn記事から直接モードページへ）を想定し、各モード先頭に300字程度のコンテキスト説明を配置する

検討したが不採用の案:
- クエリパラメータ方式（`?mode=tutorial`）: SEOとシェアUXで劣る
- タブ方式（URLに含めず）: 状態がURLで表現できずブックマーク不可
- 2階層方式（概要ページなし）: 解説セクションの置き場に困る

### 2.2 トップページと Lab 一覧の分離

**採用案**: 分離する

- `/` = ランディングページ（コンセプト訴求、最新Labのハイライト）
- `/labs` = Lab一覧（全Labを状態付きで羅列）

理由: Phase 1ではLabが1つしかないので統合してもよいが、Phase 2以降で必ず分離する必要が出る。初期から分離しておくことで後のリファクタが不要。

### 2.3 Lab概要ページ vs モードページ

**採用案**: Lab概要ページを別に置く（`/lab/render` が独立したページ）

- `/lab/render` = Lab概要（SSG、解説セクション、両モードへの導線）
- `/lab/render/tutorial` = チュートリアルモード
- `/lab/render/playground` = 自由操作モード

メリット: 解説コンテンツ（SSG、SEO対象）とインタラクティブ機能を物理的に分離できる。解説だけ読みたい訪問者の流入も取れる。

## 3. ナビゲーション構造

### 3.1 グローバルヘッダー

常時表示される固定ヘッダー。

```
[ロゴ/道場]   [稽古場]   [ロードマップ]   [道場について]                   [Zenn]
```

- **ロゴ/道場**: クリックで `/` へ
- **稽古場**: クリックで `/labs` へ（Lab一覧）
- **ロードマップ**: クリックで `/roadmap` へ
- **道場について**: クリックで `/about` へ
- **Zenn**: 外部リンク（新タブ）

モバイルではハンバーガーメニューに収納。

### 3.2 Lab内ナビゲーション（Lab概要ページ以下に出る）

Lab詳細ページ内で使うローカルナビゲーション。

```
[道場へ戻る] > [Lab 1: レンダリング] > [概要 / 稽古 / 道場]
```

- パンくず: 現在位置を明示
- モード切り替え: 概要ページ、チュートリアル、自由操作の3つをタブで切替

### 3.3 フッター

全ページ共通。

```
[フロントエンド道場について]
  - 道場とは
  - ロードマップ
  - Zenn

[規約]
  - プライバシーポリシー
  - 利用規約
  - お問い合わせ

[連絡]
  - フィードバックを送る（Google Forms）

© 2026 フロントエンド道場
```

## 4. ページ別の役割と構成

### 4.1 `/` ランディングページ

**役割**: サイトの第一印象、コンセプト訴求、Lab 1 へ誘導

**セクション構成**:
1. ヒーロー（サイト名 + 一文コンセプト + Lab 1 への大きなCTA）
2. 「何を学べるか」（Lab 1 の概要紹介、GIFや画像付き）
3. 「今後の予定」（Phase 2, 3 のLabを予告、`/roadmap` への誘導）
4. 「誰向けか」（中級フロントエンド向け、と明示）
5. フッター

**SSG対象**: はい（完全静的）

### 4.2 `/labs` Lab一覧

**役割**: 全Labを一望できるディレクトリ

**セクション構成**:
1. タイトル「稽古場一覧」
2. Labカード（各Lab 1枚ずつ）
   - Lab 1: レンダリングパイプライン可視化 [公開中]
   - Lab 2: メモリリーク稽古場 [Phase 2 で公開予定]
   - Lab 3: スクロールジャンク稽古場 [Phase 3 で公開予定]
   - Lab 4, 5, 6: [正式版で公開予定]
3. フッター

**SSG対象**: はい

### 4.3 `/lab/render` Lab 1 概要

**役割**: Lab 1 の解説、両モードへの導線、SEOランディング

**セクション構成**:
1. タイトル + 1行説明
2. モード選択（チュートリアル / 自由操作 の2つの大きなボタン）
3. 「何が学べるか」（箇条書き）
4. 解説セクション（SSG、長文、SEO対象）
   - なぜこれが重要か
   - DevToolsとの対応関係
   - 実務での応用
5. 参考文献リンク
6. 関連Zenn記事リンク
7. フィードバックボタン
8. フッター

**SSG対象**: はい（解説セクションが重要なSEOアセット）

### 4.4 `/lab/render/tutorial` チュートリアルモード

**役割**: ガイド付き学習体験

**セクション構成**:
1. ヘッダー（進捗バー、Prev/Next、ステップ番号）
2. メインエリア（可視化ビュー、大きく表示）
3. サイドパネル（現在ステップの目的、操作指示、観察ポイント、解説）
4. ステップ終了時の「次へ進む」ボタン
5. 最終ステップで「完了 → 自由操作モードへ」誘導

**SSG対象**: ステップ構造はSSG、実行はクライアント

### 4.5 `/lab/render/playground` 自由操作モード

**役割**: 制約なしの実験場

**セクション構成**:
1. ヘッダー（モード名、リセットボタン）
2. メインエリア（可視化ビュー）
3. 操作パネル（スライダー、トグル、プロパティ選択）
4. メトリクス表示（FPS、フレームバジェット、Paint/Layout/Composite判定）
5. 「チュートリアルに戻る」リンク

**SSG対象**: レイアウトはSSG、実行はクライアント

### 4.6 `/about` 道場について

**役割**: サイトの理念、作者、制作背景

**セクション構成**:
1. 道場の成り立ち
2. 何を目指しているか
3. 作者について（Rさんのプロフィール、連絡先）
4. 技術スタック紹介

**SSG対象**: はい

### 4.7 `/roadmap` 修行ロードマップ

**役割**: 今後の展開の可視化

**セクション構成**:
1. 現在公開中
2. Phase 2 で追加予定
3. Phase 3 で追加予定
4. 正式版以降
5. 「こんなLabが欲しい」の意見募集（Google Formsリンク）

**SSG対象**: はい

### 4.8 `/admin/rum` 管理者ダッシュボード

**役割**: RさんがRUMデータを見る場所

- 環境変数でアクセス制御（ベーシック認証 or 特定トークン）
- Phase 1では最小限のグラフ（日次PV、LCP分布、Lab別アクセス数）
- SSRまたはクライアント側で都度取得

**SSG対象**: いいえ（動的）

## 5. ユーザーフロー（主要な動線）

### 5.1 初見の訪問者フロー

```
Zenn記事 → / → [Lab 1を試す] → /lab/render → [チュートリアルを試す] →
/lab/render/tutorial → 最後まで → [自由操作モードへ] → /lab/render/playground →
[フィードバック] → /labs に戻る or 終了
```

### 5.2 リピーターフロー

```
/ または Zenn → /labs → 興味のあるLab → モード選択 → 体験
```

### 5.3 採用担当者フロー

```
職務経歴書のリンク → / → /about → Zenn
```

### 5.4 検索流入フロー

```
Google「Paint Layout Composite 違い」 → /lab/render（解説セクション） →
実際に試す → Lab内回遊 → サイト離脱 or Zenn誘導
```

## 6. SSG / 動的 の分類

Next.js App Router での実装方針。

**静的生成（SSG）**
- `/`, `/labs`, `/about`, `/roadmap`, `/privacy`, `/terms`, `/contact`
- `/lab/*`（概要ページ）
- `/lab/*/tutorial`, `/lab/*/playground`（レイアウト部分）

**クライアント側で動的**
- Lab内の可視化エンジン、操作パネル、計測ロジック
- フィードバックボタンの送信処理

**サーバーサイド（Edge Functions）**
- `/api/rum/collect`
- `/api/feedback`
- `/admin/rum` のデータ取得
