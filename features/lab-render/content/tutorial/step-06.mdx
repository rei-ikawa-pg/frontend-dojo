左右に **同じ要素数** を並べ、同じタイミングで動かしています。

- 左: `transform`（Composite のみ）
- 右: `width`（Layout + Paint + Composite）

理屈としては何度も見てきた通りですが、
**同じ画面で並べて動かしてみると差が目で分かる** はずです。
右側は個別の要素がカクッと動き、左側は滑らかに流れていくでしょう。

1 フレームは「走る必要があるフェーズの一番深いところまで」必ず進みます。
右側のレーンで Layout が走っている間に、左側のレーンは Composite だけで済んでいる。
**同じ「動いている」でも、ブラウザにかかる負荷は全く別物** ということが、
並べて見ると一番伝わります。

実務の最適化では、この差を自分の CSS から逆算できるようになるのがゴールです。
「transform で済むなら transform にする」の本当の理由は、ここで見た差です。
