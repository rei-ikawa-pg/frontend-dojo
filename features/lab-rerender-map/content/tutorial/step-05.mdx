state から計算した値を、さらに別の state として保持するパターン — いわゆる **派生 state** の罠です。
本ステップはラボ上の操作で再現できる挙動ではないため、コードと解説で掴んでください
（操作パネルはそのままで構いません）。

### よくある書き方

```tsx
const [items, setItems] = useState<Item[]>([])
// ❌ 派生 state
const [total, setTotal] = useState(0)
useEffect(() => {
  setTotal(items.reduce((s, i) => s + i.price, 0))
}, [items])
```

このコードは、`items` を変えた瞬間に **render → useEffect → setTotal → 再 render** の
二度手間を毎回踏みます。さらに、`items` は新しいのに `total` はまだ古い、という
一瞬の食い違いが render と render の間に生まれます。

### 正しい書き方

```tsx
// ✅ その場で計算（普段はこれで十分）
const total = items.reduce((s, i) => s + i.price, 0)
// ✅ 重い計算なら useMemo
const total = useMemo(() => items.reduce((s, i) => s + i.price, 0), [items])
```

### 「state にすべきか」の判断基準

- 元 state から純粋に計算できる → **state にしない**（その場で計算、必要なら `useMemo`）
- 非同期や外部ソースから取る、ユーザー入力の下書きを保持する → **state にする**

この基準から外れた派生 state は、高い確率で同期ズレや過剰 render の原因になります。

### 実コードでの確認

自分のコードで派生 state が疑わしい場所を見つけたら、React DevTools Profiler で
1 回の操作あたりの commit 数を数えてみてください。派生 state があるコンポーネントは
1 アクションで 2 回以上の commit が記録されがちです。
