4 種類のリーク中、もっとも気付きにくいのが **Closure リーク** です。
「関数が何かを覚えている」という抽象的な概念が、メモリ上で具体化するとどうなるかを見ていきます。

### 観察のポイント

- 保持サイズを **大 (500K)** に、対策を **対策なし** にする
- 「1 サイクル実行」を数回押す → ヒープが数十 MB 単位で増える
- 対策を **cleanup あり** にして同じ操作をすると、一切増えない

### 実務コードで当てはめると

```tsx
function Chart({ data }: { data: number[] }) {
  // ❌ data をキャプチャしたコールバックを外に渡すと、
  //    data が外の寿命に引きずられてしまう
  useEffect(() => {
    eventBus.on('tick', () => analyze(data))
    // cleanup を忘れると：eventBus が data を抱えたまま
  }, [data])
}
```

### 「Closure を切る」発想

cleanup する、が最短の解決策です。加えて設計レベルでは、
- 大きな配列を参照する関数を外側に渡さない
- どうしても渡すなら `useCallback` + 弱い参照 / ID 経由

といった「関数と巨大データを切り離す」発想が効きます。
