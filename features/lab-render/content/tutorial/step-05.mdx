ここまで 3 つのプロパティで挙動が違うことを見てきました。
これは <Term id="css-triggers">CSS Triggers</Term> と呼ばれる資料にまとまっていて、
Blink のソースコードにも同じ関係が埋まっています。

つまり:

- どのプロパティがどこまでのフェーズを引き起こすかは、**ブラウザの実装として決まっている**
- ブラウザは個別プロパティに合わせて、必要最小限のフェーズで済ませるように作られている

今回のステップでは `opacity` を有効にしています。
理論上は <Term id="composite">Composite</Term> のみで済むプロパティです。
ただし Theory vs Actual テーブルは <Term id="loaf">LoAF</Term> の仕様上 Paint と Composite を分離できないため、
`Paint + Composite` 行に合算表示されます。
この行の 理論 列に ● が点灯し、`Layout` 行は消灯するのが期待値です。

実測側は、フレームが 50 ms を超えないと LoAF が発火しない仕様のため、
軽い opacity 単独では `—`（未計測）になることがあります。
その場合は道場モードで要素数を増やすと、`Paint + Composite` 行の実測が乗り、
**理論と実測が一致する** ことを体で確認できます。
あとは自分の選んだプロパティが「どこまで引き起こすか」を理論表から読めばよい、という勘が育ちます。
