# フロントエンド道場 Phase 1 MVP 要件定義ドラフト

最終更新: 2026-04-17 / ステータス: ドラフト（R調整待ち）

## 0. 全体サマリー

Phase 1 MVPは「共通計測基盤 + Lab 1（レンダリングパイプライン可視化）」の初回公開版。Month 1〜2でリリース。Chromium完全対応、Safari/Firefox は graceful degradation、モバイルはPC推奨表示 + 基本閲覧可。

---

## 1. 機能要件

### 1.1 トップページ (`/`)

**必須機能**
- サイトコンセプトの一文表示（「フロントエンドの鬼門を、読むのではなく触って理解する」）
- 現在公開中のLab一覧（Phase 1ではLab 1のみ、他は「近日公開」ラベル）
- Phase 2, 3 のロードマップ（「次はメモリリーク稽古場」「次はスクロールジャンク稽古場」）
- GitHubリポジトリへのリンク
- Zenn記事へのリンク
- フィードバックボタン（フッター）

**推奨機能**
- ヒーローセクションでLab 1の短いループ動画（MP4 or WebM、軽量）
- 「誰向けのサイトか」の明記（中級フロントエンド向け）
- 「なぜ作ったか」のブログ的な短文

**作らない**
- ログイン / アカウント機能
- コメント欄
- 検索機能

### 1.2 Lab 1: レンダリングパイプライン可視化 (`/lab/render`)

#### 共通UI
- Labタイトル + 1行説明
- モード切り替えタブ（チュートリアル / 自由操作）
- サイドバー or ヘッダーに「Lab一覧へ戻る」「共通ダッシュボードへ」
- ブラウザ非対応時の警告バナー（「この機能はChromium推奨です」）

#### チュートリアルモード（`/lab/render/tutorial`）
- ステップ制御（Prev / Next / 進捗バー）
- 各ステップに「目的」「操作指示」「観察ポイント」「解説」を配置
- ステップ数: 5〜8（初版の目安）
- 例: Step 1「Layoutが走る例を観察」→ Step 2「Paintだけで済む例に変える」→ Step 3「Compositeだけで済む例を作る」...
- ステップ毎に可視化ビューが連動（1万要素のグリッド + Paint/Layout/Compositeを色分けハイライト）
- 「次のステップへ」ボタンの活性化タイミング（固定 or 操作完了検知）

#### 自由操作モード（`/lab/render/playground`）
- 要素数スライダー（100〜10000）
- CSSプロパティのトグルボタン群（`transform`, `top`, `width`, `opacity`, `background-color`, `box-shadow` 等）
- 「Layout / Paint / Composite のどこまで走ったか」リアルタイム表示
- FPSメーター
- 「現在のフレームバジェット消費」表示（16.67ms のうち何ms使ったか）
- プロパティをクリックすると対応する要素がハイライトされる
- リセットボタン

#### 解説セクション（Labページ末尾、SSG）
- 「なぜこれが重要か」「DevToolsでどう見るか」「実務での応用」
- DevToolsのPerformance panelとの対応関係を図解
- 関連Zenn記事へのリンク
- 参考文献（web.dev、MDN、Blinkソース等）

### 1.3 共通計測基盤（自前RUM）

#### 収集メトリクス
- **Core Web Vitals**: LCP, INP, CLS, FCP, TTFB（web-vitalsライブラリ経由）
- **Long Animation Frames**: LoAF API（対応ブラウザのみ）
- **カスタムメトリクス**: 
  - 各Labでのフレームレート
  - ユーザー操作から次フレームまでのレイテンシ
  - メモリ使用量（`performance.memory`、Chromium限定）
- **コンテキスト情報**: デバイス種別、画面サイズ、ブラウザ、Lab ID

#### データ送信
- `PerformanceObserver` でメトリクス収集
- `navigator.sendBeacon` でCloudflare Workersエンドポイントに送信
- バッチ送信（個別イベントではなく集約）
- サンプリング率（MVPは100%、負荷が見えてきたら調整）

#### 可視化
- 管理者用ダッシュボード（`/admin/rum` 等、ベーシック認証 or 環境変数制御）
- 公開ダッシュボード（`/dashboard`）: 匿名化された全体メトリクス（任意、MVPでは後回しでもOK）

### 1.4 アナリティクス統合
- Cloudflare Web Analytics のタグ埋め込み
- クッキー同意バナー不要
- カスタムイベント送信は不要（RUMが担う）

### 1.5 フィードバック機能
- 各Labページ末尾にシンプルなGood/Badボタン
- 押下時に任意1行コメント入力可能（スキップもOK）
- Cloudflare Workers経由でD1に保存
- フッターにGoogle Formsへのリンク（詳細なフィードバック用）

### 1.6 ナビゲーション・共通UI
- ヘッダー: ロゴ、Lab一覧、GitHubリンク、Zennリンク
- フッター: コピーライト、プライバシーポリシー、利用規約、問い合わせ（Google Forms）、フィードバックボタン
- ダークモード固定（MVPではライトモード切替なし）

### 1.7 エラー・フォールバック
- 404ページ（`/not-found`）
- ブラウザ非対応時の代替画面（「この機能はChromium推奨です」+ 解説セクションは表示）
- JavaScript無効時の最小コンテンツ表示（SSGの解説部分だけは読める）
- WebGL非対応時のフォールバック（Canvas 2D版の簡易表示）

### 1.8 法的・運用ページ
- プライバシーポリシー（`/privacy`）: RUMで何を収集するか明記
- 利用規約（`/terms`）: 免責事項、学習目的、広告なし明記
- お問い合わせ（`/contact`）: Google Formsへのリンクでも可

## 2. 非機能要件

### 2.1 パフォーマンス
- **初回ロード（トップページ）**: LCP < 2.5s（モバイル4G想定）
- **各Labページ**: LCP < 3.0s（重いインタラクティブ機能含むため）
- **INP**: < 200ms（全ページ）
- **CLS**: < 0.1
- **バンドルサイズ**: 初期JSは200KB以下（gzip後）、Lab個別JSは遅延ロード
- **低スペック端末での目標**: 5年前のAndroid端末で30fps以上（Lab 1）

### 2.2 アクセシビリティ
- キーボード操作対応（Tabキーで全要素到達可能）
- スクリーンリーダー対応（aria-label、role等の適切な付与）
- カラーコントラストWCAG AA以上
- `prefers-reduced-motion` の尊重（アニメーション減らす）

### 2.3 SEO
- メタタグ（title, description, OGP）を全ページで設定
- 構造化データ（JSON-LD、Article or TechArticle）
- サイトマップ（`/sitemap.xml`）
- robots.txt
- canonical URL 設定
- 各Labページに日本語のディスクリプション200字程度

### 2.4 セキュリティ
- Content Security Policy（CSP）設定
- HTTPS強制（Cloudflare Pagesで自動）
- RUMエンドポイントに基本的なレート制限
- 管理者ダッシュボードは環境変数経由で保護

### 2.5 可用性
- 目標稼働率: 99%（個人開発の範囲で）
- Cloudflare Pagesの無料枠内で運用
- 障害検知は手動（Cloudflareのメール通知のみ）

## 3. データ要件

### 3.1 RUMデータ項目
- `timestamp`: ISO8601
- `session_id`: 匿名UUID（セッション単位、cookie不使用、sessionStorage）
- `lab_id`: 'render' 等
- `mode`: 'tutorial' or 'playground'
- `browser`: User-Agent から抽出
- `device_type`: 'desktop' / 'mobile' / 'tablet'
- `metric_name`: 'LCP' / 'INP' / 'FPS' / 'memory' 等
- `metric_value`: 数値
- `metadata`: JSON（Labごとのカスタムフィールド）

### 3.2 保存先・期間
- Cloudflare D1（無料枠内）
- 保存期間: 90日（無料枠超過しない範囲）
- 90日経過データは自動削除（Cron Trigger）

### 3.3 プライバシー
- 個人特定情報は一切収集しない
- IPアドレスは保存しない
- UAは集計用のみ、生データは保存しない
- プライバシーポリシーで明記

## 4. コンテンツ要件

### 4.1 日本語文章の方針
- 中級フロントエンド向けトーン（初心者向けに噛み砕きすぎない）
- 敬体（「です・ます」）ベース
- 道場メタファーを節度を保って使う（濫用しない）
- 専門用語は初出で英語併記（例: 「再描画（Repaint）」）

### 4.2 Lab 1 チュートリアルシナリオ（草案）
1. **導入**: 「ブラウザは1フレームをどう描くか」の概念図
2. **Layout を走らせる**: `width` を変える例、全体が再計算される様子
3. **Paint だけで済む**: `background-color` を変える例、Layoutがスキップされる様子
4. **Composite だけで済む**: `transform` を使う例、Paint もスキップされる様子
5. **実測で確認**: FPSメーターとフレーム内訳で差を観察
6. **応用**: 実務で出会う「重いアニメーション」の例と修正
7. **DevToolsとの対応**: Performance panel のどこに何が現れるか
8. **まとめ + 次のLabへ**

### 4.3 UIコピーの語彙
- ボタン: 「次へ進む」「戻る」「試す」「リセット」
- モード: 「稽古（チュートリアル）」「道場（自由操作）」
- 進捗: 「修行の進み具合」「◯段目 / ◯段中」（道場メタファー）
- 評価: 「役立った / 改善してほしい」（Good/Bad）
